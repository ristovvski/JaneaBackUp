## 2. WF-ICP-Score: формат заметки и падение Path B — СДЕЛАНО, ждёт Nik

### Формат заметки в Pipedrive

Заметка приходила одним сплошным абзацем. Причина не в том, что Pipedrive
«схлопывает `\n`» — **поле активити рендерится как HTML**, а для браузера
перенос строки это пробел.

Установлено десятью пробами на активити 46845: `<b>`, `<strong>`, `<i>`,
`<br>`, `<p>`, `<ul><li>` сохраняются дословно; `<script>` вырезается вместе со
всей заметкой; одиночный `<` в тексте возвращается как `&lt;`, `&` как `&amp;`,
а уже экранированный `&lt;` не трогается; `\r\n` искажается в ` \n`.

Экранирование на входе и доказывает рендеринг на выходе. Отсюда два правила:
**никаких `\n` для вёрстки** и **ничего не экранировать вручную** — Pipedrive
делает это сам, ручное дало бы `&amp;lt;`.

Готовый блок для колонки Clay и полная таблица проб — в
`icp-scoring/engine/clay_note_format.md`. Проверено сквозь весь конвейер:
активити **47033**, 1 320 символов, байт в байт.

Nik блок вставил — заметка в новом виде приходит корректно.

### Падение Path B

Исполнение **65816**, алерт «failed at Dedupe B / Unknown error [line 95]».

Тело пришло с **16 ключами** — все скоринговые плюс новая HTML-заметка, но без
`request_id`, `org_id`, `deal_id`, `requested_at`. При вставке блока `note`
заменился и объект вокруг них.

**Это правка на стороне Clay, не n8n.** Контракт — `engine/clay_callback_column.md`:
восемь обязательных ключей, первые пять эхом из webhook-колонок.

Попутно закрыто четыре наших дефекта, из-за которых алерт был бесполезен:

1. `Dedupe B` был границей и падал выше всех страховок → теперь пропускает
   событие без ключа неотмеченным, отказ делает `ParseScored`, который
   перечисляет все нарушения сразу.
2. У `Dedupe B` не было error-output → добавлен, плюс статик-тест: ничего до
   write-gate не имеет права умирать вне loud-ветки.
3. Failure-активити пыталась создаться без организации (`Number(null)` = 0,
   Pipedrive отвечал *Bad request*) → добавлен `IF error has an org?`.
4. Slack-алерт повторял замаскированную ошибку вместо списка проблем → теперь
   ведёт списком, который `BuildErrorContext` восстанавливает повторной
   валидацией.

Пятое, вскрывшееся при починке четвёртого: **перенос строки внутри `{{ }}`
должен быть escape-последовательностью**, иначе n8n отвечает
`{"error":"invalid syntax"}`, а `continueOnFail` это глотает. Закреплено тестом
по всем выражениям графа.

Сейчас та же полезная нагрузка даёт в Slack восемь названных проблем вместо
«Unknown error [line 95]», исполнение краснеет, WF-ERR срабатывает.

**Состояние:** 38 узлов, active. **Блокер: Clay-колонка должна вернуть четыре
ключа.** До этого Path B будет отбивать каждый колбэк — громко и правильно.
