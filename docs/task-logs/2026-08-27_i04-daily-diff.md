## Improvable

1. **The diff has a false-positive class it escalates hardest on.** A lead→deal conversion is
   indistinguishable from a hard delete by the diff's current test (404 on detail read). Today that
   was 13/13 false positives on the check the job is built to escalate loudest. Without the deal
   cross-check this post would have been a false alarm about 11 lost meeting-stage leads. Check 1
   needs a "was a deal created for this person at the departure timestamp?" arm before it prints
   `irreversible, escalate`. Not fixed here — fixes belong to the owning session.
2. **Closed a documented open guess.** The 08-26 post recorded `"add"`/`"delete"` webhook action
   values as unverified (only `"change"` observed). `delete` is now observed live 6×: v2 shape is
   `data: null` with `previous` holding the last state, `meta.action: "delete"`.
3. `.env` line 30 (`REQUESTS_CA_BUNDLE`) is an unquoted Windows path with a space, so
   `set -a && . ./.env` fails that line in Git Bash and leaves the variable unset. The walk
   succeeded on the system trust store anyway, but the documented load step is silently broken.
4. Scheduled-task runs of this job should assert that yesterday's snapshot exists and say so when
   it doesn't — a 7-day diff silently labelled "daily" is how a gap stays invisible.
