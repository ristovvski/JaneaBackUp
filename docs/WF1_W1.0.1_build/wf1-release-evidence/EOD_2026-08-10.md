## Recoveries

WF-2R and WF-2S cycling clean. **The dedupe canonicalization proved itself three times on live
traffic** — reconciler replays of already-delivered replies were suppressed instead of producing a
second forward. That was the flip's single largest correctness risk.

## Incidents and resolutions

1. **Reply alerts had never worked — 25/25 executions, 11 days, zero posts.** Real JavaScript in an
   n8n *expression* on a node that swallows errors: the node failed, the execution still reported
   `success`, and a check asking "did the node run?" answered yes. Fixed; alert now proven on the
   wire with a permalink.
2. **`Ops Warn Classify` was broken the same way** — uncertain classifications were silently
   review-routed with nobody told. Fixed in the same sweep.
3. **`write_mode_max_hours` stuck at 0 for ~3 hours**, alarming every cycle. A restore living in a
   `finally` block of a stalled background process never ran. Restored; the monitor now asserts
   production config every pass so this is caught in one cycle, not by a human reading spam.
4. **Alert suppression burned on failure.** The gate keyed on the `3. Responded` label — written by
   Make, Zaps, backfills and humans, never a delivery receipt. A failed post still consumed a
   lead's single alert forever. Now an own registry set **only** on Slack `ok:true`.

## The headline cost of the old design — now closed

**1,713 leads** (of 57,602) carry `3. Responded`. Under the previous label-based gate, **every one
of them would have had its next reply silently suppressed** — no notification, nothing visibly
wrong. Most of those labels were written by Make. With the delivery-registry gate live this is
historical context, not an open hole.
