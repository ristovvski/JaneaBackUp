**Date:** 2026-07-21  **Base:** W1.0.13 (`698d2433`, 95 nodes)  **Now live:** W1.0.13.1 (`da23d080-a0e0-4126-81c0-0cca60908435`, 95 nodes, ACTIVE)

## TL;DR
The event-campaign naming contract becomes **two brackets**: `[Events Visiting] [Event Name] - {free text}`. Bracket 1 = hypothesis marker, bracket 2 = the exact Event name (verbatim, dashes allowed), anything after = ignored free text. This replaces W1.0.13's positional first-segment parsing, so the human rule is now just "event campaigns have two brackets" and every deviation is machine-catchable. The OLD single-bracket form is now explicitly non-canonical -> ops warn. Parser-only change (no node count change).

## Parser diff (Normalize node only)
Old (W1.0.13): one `[..]` group; Event name = name minus that bracket, trimmed of ws + leading/trailing `-` (positional).
New (W1.0.13.1):
- Scan ALL `[..]` groups in order.
- Group 1 (lowercased) -> `event_marker_canon` -> Marketing Hypothesis (unknown -> not written, no warn).
- Group 2 -> Event name VERBATIM (surrounding whitespace trimmed only; dashes inside legal, e.g. `[Web Summit - Lisbon 2026]`).
- Text after group 2 + any 3rd bracket -> ignored (free-text zone).
- Guardrail (ONLY when group 1 is canonical = a recognized event campaign): no 2nd bracket / empty 2nd bracket / event name >60 chars -> skip trio + ops warn. This also catches the **old single-bracket form** `[Events Visiting] - Ai4 2026` (now non-canonical).
- No bracket -> fully inert. Unknown group 1 -> event name from group 2 only, hypothesis skipped, no warn.

New warn text: `WF-1: event campaign "{campaign.name}" is missing/has an invalid [Event Name] bracket - trio skipped; fix the campaign name`.

**Unchanged:** write sites (Person Create + Person Patch Invited + M5 Person Patch Accepted), their gates, the `IF Event Marker Bad -> Event Marker Warn` tee, CONFIG, selectLead, lead title, lead Campaign field. Full `campaign.name` still flows verbatim into title + Campaign field (campaign-match bracket-safe, asserted).

Deterministic patcher (`patch_wf1_w1013_1.py`), byte-identical re-run. Parser probed against 11 cases before tests (all correct).
