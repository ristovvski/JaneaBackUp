## Change 1 — union label semantics (M5 & M7 Labels Compute)
Replaced replace-semantics (`existing − ourLabels + [target]`) with **union**:
```js
const targetSet = [];
if (effectiveRank >= 1) targetSet.push(cfg.labels.cold);
if (effectiveRank >= 2) targetSet.push(cfg.labels.connected);
if (effectiveRank >= 4) targetSet.push(cfg.labels.responded);
const label_ids = Array.from(new Set([...existing, ...targetSet]));   // never removes
const changed = !(existing.length === label_ids.length && existing.every(id => label_ids.includes(id)));
```
- Foreign labels preserved (union never removes) → union-compatible with parallel automation `25112064`.
- **Skip-empty-PATCH:** new `M5 IF Labels Changed` / `M7 IF Labels Changed` gates on `$json.changed`. The existing `IF Lead ID` gate could NOT be reused — M7's reads `$('M7 Build').lead_id` (not the compute output) and both false-branches post a "no lead" warn, so extending them would misroute no-ops to a spurious warn. Wiring: `IF Lead ID(true) → IF Labels Changed → [Lead Patch, skip]`; M7 skip re-joins `M7 IF Reply Activity Lead` so reply activity still flows. No cycles.
- Sent-path `Create Lead` already starts `[cold]` — **verified unchanged**.
