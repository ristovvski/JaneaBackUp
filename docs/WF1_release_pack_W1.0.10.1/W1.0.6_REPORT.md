## Defect fixed
Surfaced 2026-07-15 on W1.0.5 double execs **9992/9995**: Pipedrive v2 `POST /activities` returns **400 "Validation failed: note: This value is too short."** when `note` is an empty string. The sent-path builder used `note: n.invite || ''`, so a `connection_request_sent` with no `connection_message` sent `note:""` → 400 → the sent execution errored (org/person/lead already created; invite activity lost). Real LinkedIn invites are frequently sent with no note → HIGH real-world hit rate. Pre-existing; **not** a W1.0.5 regression.

## Changes (micro-patch, 2 nodes)
1. **`Create Activity`** (sent path, already a Code-built IIFE): dropped `note` from the object literal; add it back only when non-empty — `const note = n.invite || ''; if (note !== '') body.note = note;` (same idiom as the existing `lead_id` / F13 `organization_id` guards).
2. **`M7 Reply Activity`** (reply path): converted the inline `={{ JSON.stringify({…}) }}` to the Code-built IIFE idiom and guarded `note` the same way (`note = reply_text`). Em dash normalized to the ASCII-safe `—` escape (consistent with the F13 nodes).

`M6 Activity` and `M8 Task` carry no `note` field (verified) — nothing to change.

## Static — 41/41 (3 new, discriminating)
Added: Create Activity omits note when `connection_message` empty/absent & keeps it when present; M7 Reply Activity is a Code-built IIFE that omits note when `reply_text` empty & keeps it when present; a guard that no activity/task body sends an unconditional empty-able note. The 3 new tests **fail on W1.0.5** (38/41) and pass on W1.0.6 (41/41) — they actually catch the bug.
